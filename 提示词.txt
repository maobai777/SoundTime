# 项目：本地音频虚拟麦克风播放器 (SoundPad Clone)

## 1. 项目概述
开发一个轻量级Windows桌面应用，无需登录，界面极简。核心功能：**将用户选择的本地音频文件（WAV/MP3），直接“注入”到系统的麦克风输入通道**。效果类似于硬件音响对着麦克风播放，但完全在软件内部完成。

## 2. 技术栈与约束
- **语言**: C++ (兼容Win32原生API)
- **UI框架**: 纯Win32 API (CreateWindow, 对话框等)，无额外依赖
- **音频处理**: Windows Core Audio APIs (MMDevice, WASAPI, AudioClient)
- **解码**: 使用`msacm32.dll` (ACM) 解码WAV；MP3可选`mfplat.dll` (Media Foundation) 或拒绝MP3，先保证WAV支持
- **无需登录**: 无网络请求，无注册表写入(除必要的COM初始化)
- **最低系统**: Windows 10/11 64位

## 3. 核心功能需求
### 3.1 音频播放至麦克风
- 创建一个**虚拟音频捕获端点**？不对——更简单的方案：使用**回环注入**。实际Windows无法直接向物理麦克风驱动写数据。应采用替代方法：
  - 方案A（推荐）：创建一个新的虚拟音频设备（需要驱动，复杂）。不采用。
  - 方案B（实用）：通过WASAPI在**麦克风数据流上叠加播放的音频**——这需要中间驱动程序，复杂。
  - 方案C（对用户透明但需配置）：程序**输出到扬声器，但用户需物理连接Line-in到Mic** — 不符合预期。
  
**更正实现思路**：既然用户要求“在麦克风里面播放”，现实软件（如SoundPad, Voicemod）是通过虚拟声卡驱动实现的。纯用户态代码无法注入真实麦克风流。因此，本程序应提供一种**便捷方式**：  
✅ **实际可实现功能**：程序播放音频到**默认音频输出设备**，但同时提供一个**虚拟音频捕获设备**（需要安装虚拟驱动，过于复杂）。  
✅ **更佳折衷**：程序提供一个**混音器窗口**，用户可选择“播放到扬声器/耳机”，或者如果系统安装了VB-Cable等虚拟电缆，可选择将其输出到虚拟电缆的输入，虚拟电缆的输出作为麦克风使用。

由于驱动开发超出范围，我会采用以下最简可行方案：  
**本程序生成一个WASAPI输出流，允许用户选择目标设备（如“CABLE Input”）。并在界面上说明需要安装免费虚拟音频电缆（如VB-Cable）来实现麦克风注入。** 并提供一键打开系统“声音设置”帮助用户设定虚拟电缆为默认麦克风。

## 4. 界面设计 (Win32)
- 主窗口大小: 300x150，无边框或经典边框
- 组件：
  - 标签：“选择音频文件” 
  - 按钮：“打开文件” (点击打开文件对话框)
  - 文本框显示文件路径
  - 播放/停止按钮
  - 音量滑块 (控制播放到目标设备的音量)
  - 目标设备下拉列表 (枚举所有WASAPI渲染设备)
  - 辅助链接：“安装虚拟电缆 (推荐)” 打开官网
  - 状态文本：“就绪” / “播放中...”

## 5. 音频播放逻辑 (使用WASAPI)
- 使用`IMMDeviceEnumerator`获取指定渲染设备
- 初始化`IAudioClient`，采用共享模式 (ShareMode = Shared)
- 音频格式：PCM 48000Hz, 16位, 立体声
- 文件解码：使用ACM将WAV文件转换为匹配的PCM格式
- 播放线程：从解码缓冲区读取数据，循环填充WASAPI的`GetBuffer`，直到播放完毕或用户停止

## 6. 重要提示（将包含在生成的代码注释中）
- 因为真实麦克风注入需要驱动，本程序通过让用户选择虚拟电缆输出端来实现相同效果。
- 如果用户未安装虚拟电缆，程序仍可正常播放到扬声器/耳机。
- 为了提高易用性，程序提供“设置此设备为默认麦克风”快捷链接（打开 `ms-settings:sound` 或 `mmsys.cpl`）。
